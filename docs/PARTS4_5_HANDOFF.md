## Working behavior

- Exact bigint input conversion; no rounding of excess precision. Dynamic token decimals, tick/lot/minimum checks; bounded expiry; buy/sell limit, IOC, FOK and post-only. No unsupported ordinary reduce-only option.
- Fresh market/SDK margin and capacity checks, including the `priceable` union and actual `placeable`/`sufficient` flags. `limitedBy` is displayed as the binding size constraint, not automatically treated as a rejection.
- SDK-built, byte-checked unsigned order using a build-only executor that always refuses execution. Actual-actor `eth_call`, gas estimate plus 30% gas and 2× gas-price buffers, STT budget and balance checks. Book estimate covers at most 10 visible levels and makes no fill promise.
- Direct EOA only: owner must equal actor. Wallet account, chain and genesis checked immediately before signing, alongside fresh deployment and simulation checks. Smart accounts, linked operators and linked-main funding are blocked pending their separate integration.
- Explicit per-order confirmation, fresh recheck before opening the wallet, review expiration after 30 seconds and invalidation after edits/identity changes. Increased margin/pull or gas requires a new review. Builder and builder fee are zero; no token approval or deposit is automatically sent.
- Local attempt saved before `eth_sendTransaction`, immediate hash capture, origin/owner cross-tab send lock, separately locked journal writes, no automatic write retry. Code 4001 is explicit rejection; other wallet errors remain outcome-unknown. Reloaded pre-sign attempts remain unresolved.
- Inspector verifies chain/genesis, registered pool, transaction sender/target/value/calldata and canonical receipt block. `decodePlaceOrder(receipt, pool)` supplies actual receipt fills. Current order reads and parent/receipt/current block positions provide reconciliation context without claiming that an entire block's delta is caused by this one transaction.
- A separate explicit cancellation review simulates the verified `cancelOrder(uint128)` call, then uses the same wallet boundary. Cancellation/expiry events are inspected independently; cancellation never claims to close a position.
- Missing hashes can be recovered from wallet activity only once a mined transaction matches the saved intent. Wrong transactions are rejected. A successful receipt with no execution evidence remains an unresolved business outcome.

## Demo and live gate

1. Start `npm run dev`; inspect public markets and account data with no wallet.
2. With a dedicated funded EOA ready, connect in Positions. Select Hideki 50383 in the wallet yourself and reconnect after a network change.
3. Choose an allowed market in Trade. Enter a small exact quantity/price and review the STT budget. Run preflight; verify owner, bound, expiry, funding and unsigned call.

5. If a remainder is resting, use the separate cancellation preflight/confirmation. Inspect its receipt and refresh full exposure in Positions.

## Limits

- No real browser-extension signature or live placement/cancellation has been verified. Wallet readiness, STT and allowed paper collateral are required.
- Direct owner orders can use **existing** MarginBank allowance to pull a shortfall. The UI warns that preview funding is not a contract-enforced cap. Contract state may change between simulation and execution. Wallet-side fee edits can change the final transaction cost.
- Cross-tab protection applies only to this origin and preserved storage, not other apps/devices. Browser storage is editable and clearable; it is not an audit ledger. The journal holds at most 1,000 attempts and blocks on malformed/overflowed storage rather than silently dropping unresolved records.
- Known-hash receipt polling and verified missing-hash recovery are implemented. Automatic nonce replacement resolution, changed-calldata replacements, full evidence exports and recovery of a rejected prompt lost during a reload remain Part 6. Never clear unresolved records to bypass a blocked send without independently establishing their outcome.
- Inspector state is block-scoped, not exact transaction-isolated position accounting. Receipt fills prove this transaction's fills; later fills require historical reconciliation in subsequent parts.
- Owner-only cancellation is currently reached from a locally evidenced attempt, not every externally created resting order in Positions.
- Risk Lab, indexed history, Developer Test Lab UI, native stops, voucher/deposit/withdrawal UI, delegated trading, public hosting and submission are not completed by these parts.
- The existing SDK bundle size warning and development-only dependency advisory remain. No complete security audit is claimed.
